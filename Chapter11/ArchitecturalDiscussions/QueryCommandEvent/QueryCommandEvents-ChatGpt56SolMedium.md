# Prompt 2026-09-13

Check where to use Commands and queries between Bounded Contexts. Use the domain knowledge graph.

[Domain Knowledge Graph](../../assets/larderEnahnced4.ttl)

# Answer

**Use queries to read another context’s data; send a command to the context that owns a requested change.** The graph explicitly labels the cross-context reads as queries (`qry`). It does not establish a cross-context command contract: its named commands come from the EventStorming board, while the context canvases leave the likely command boundaries open.

| Boundary                                                                  | Use                                                                     | What the graph supports                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Meal Planning → Recipe Catalog                                            | **Query**                                                               | Fetch recipes for selection. Cooking Assistance and Meal Preparation also read recipe data, although their canvases route some reads through Meal Planning.                                                                                           |
| Cooking Assistance → Meal Planning; Meal Preparation → Meal Planning      | **Queries**                                                             | Read the menu and related planning data. Meal Preparation also queries Cooking Assistance for a help response.                                                                                                                                        |
| Cooking Assistance or Sharing → Media                                     | **Queries**                                                             | Retrieve pictures for a help request or for sharing the finished meal. Taking pictures is a separate Media action on the EventStorming board.                                                                                                         |
| Sharing → Consent Management                                              | **Query**                                                               | Check consent before showing content. The Cook Profile → Consent Management “Consent” message has kind `?`, so **recording or changing consent needs a decision**; if Consent Management owns that change, address a command there.                   |
| Meal Planning or Meal Preparation → Cooking Assistance                    | **Command candidate for requesting help; query for reading the answer** | The board calls the user action “Request help”; the canvases explicitly show *Help response* as a query. Treat a new help request as an action at the help owner, subject to settling whether Cooking Assistance and Cooking Help are one context.    |
| Cooking Assistance ↔ Grandma Avatar AI; Cooking Assistance → Notification | **Events as drawn**                                                     | The canvases label help-request and help-response exchanges with the avatar, and notifications of those exchanges, `evt`. Whether assigning an avatar to answer needs an explicit command is still an open question.                                  |

Before fixing the contracts, resolve three ownership issues: who writes **Ingredient** (Meal Planning or Recipe Catalog), whether **Cooking Help** is distinct from **Cooking Assistance**, and why Sharing reads **Help response** from Meal Preparation when the canvases attribute help ownership to Cooking Assistance. Those answers determine the correct destination for commands and the authoritative source for queries.
